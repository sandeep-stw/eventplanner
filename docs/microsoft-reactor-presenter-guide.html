Your goal as presenter

Show how a shopper goes from event requirements to a curated, priced plan—and how that plan is saved only after the shopper approves the displayed total.

Important: start from what is already in your environment. The EventPlanner solution is already available. Do not rebuild or re-import it. Use the deployed agent, flows, data, and Dataverse tables. The repository is reference material, not a tenant export.
Be clear about the demo boundary. This demo saves an Event Plan. It does not take payment, reserve stock, or place a supplier order.

If you make a separate demo solution

Reuse the existing tables with Solutions → your demo solution → Add existing → Table. Add Theme, Product, Theme Product, Event Plan, and Event Plan Line as needed. Choose the existing tables—do not create duplicates. Reuse their data; do not import the sample CSVs again into the same environment. For the fastest presentation, stay in the existing EventPlanner solution.

Before you present

Day before

  • Sign in to the correct Power Platform environment and open EventPlanner.
  • Open the existing Theme Studio agent. Do not paste repository YAML over working topics; source YAML may contain placeholder flow IDs.
  • Verify the deployed GetThemes, GetThemeDetails, BuildEventPlan, and SaveEventPlan flows are on and connected.
  • Check Tropical Luau (TROP) is active and its mapped products are available and in stock.
  • Rehearse the complete journey. Confirm totals and saved rows in the live environment.
  • Open the solution, agent test pane, and Dataverse Event Plans view in separate tabs.
  • Use a demo account and demo data. Keep customer information and credentials off screen.

Ten minutes before

  • Start a fresh test conversation and check the selected environment.
  • Check screen sharing, browser zoom, network, and notifications.
  • Have a successful pre-run screenshot or recording ready; identify it honestly as a backup.
  • Use a dedicated demo environment for writes. Do not delete records during the presentation.
  • Know where to find Event Plans by the plan number returned in chat.
Use live results as authoritative. Sample figures below are rehearsal checks, not guarantees. Verify them in the actual environment before quoting them.

Live walkthrough: what to do and what to say

Use the Copilot Studio test pane for a controlled presentation. Keep the environment and Dataverse tabs ready, but spend most of the live demo in the conversation.

1
0–3 minutes · Welcome

Set the scene

Do: Show the agent and introduce the shopper scenario.

Imagine you're planning a birthday for 40 people. You want a theme, a shopping list that fits your budget, and a clear way to save the plan if you like it.

Explain: This is a planning and demo-order experience, not payment or fulfilment.

2
3–6 minutes · Architecture

Show the existing solution

Do: Briefly show the already available EventPlanner solution, then return to the agent. Avoid changing or rebuilding components during the demo.

The conversation is the front door. Power Automate handles the repeatable data and calculation work, and Dataverse holds the catalog and saved plans.

Highlight: The components already exist in this environment; the audience is seeing them work together.

3
6–9 minutes · Curated catalog

Show how products are governed

Do: In Dataverse, briefly show Themes, Products, and Theme Products. Point to the relationship between a theme and its selected items.

The model isn't asked to invent a shopping list. The mapping says which products belong to a theme; the flow uses that data to build the plan.

Keep it brief: The point is the curated boundary, not a tour of every column.

4
9–21 minutes · Live shopper journey

Discover and recommend

Do: Start a fresh conversation and type:

Plan a birthday for 40 people.

Answer the prompts with Birthday, 40, Bright & Tropical, and a budget of 400. Choose Tropical Luau from the returned themes.

The agent is collecting structured requirements. Those answers guide which themes are relevant before the plan is priced.

5
Continue · Explain pricing

Make the flow work visible

Do: Let the selected theme's shopping plan render. Point to included items, quantities, total, estimated setup time, and any excluded item.

The flow retrieves products mapped to this theme, calculates quantities and totals, and applies the budget rules. The agent explains those results; it shouldn't make up prices.

If verified live: The sample Tropical Luau plan for 40 guests at a £400 budget is expected to total £379.82, show about 3.5 hours setup, and exclude the Neon LED Sign. The expected approved plan has 11 included lines. Only quote these if your rehearsal confirms them.

6
21–25 minutes · Adjust

Change a requirement

Do: Ask the agent to change the budget, for example:

Change my budget to 600.

Use the exact wording you tested in the target agent. Show that it reprices the current theme. Return to 400 if needed for the agreed save scenario.

A change to one requirement triggers a fresh calculation against the same selected theme.

7
25–29 minutes · Approval and save

Save only after the shopper approves

Do: Check the displayed total. Choose Yes, create my order only if you are comfortable creating a demo record.

You can see the price before anything is saved. This confirmation is the boundary: the agent creates a plan only after you approve it.

Be precise: Say “saved Event Plan” or “demo order record.” Do not say a payment was taken or a supplier order was placed.

8
Verify · Dataverse

Show the business record

Do: Open the new Event Plan using its returned plan number. Show its status, total, guest count, and related Event Plan Lines. Compare the included lines to the products displayed in chat.

The result is inspectable business data, not just a transcript. The plan and line items can support follow-up and future integrations.

Optional branch, only if you are ahead of time

  • Theme details: Ask for the theme's description, palette, mapped core items, or styling tips if verified in rehearsal.
  • Budget shortfall: In a fresh conversation, use a low budget and explain the live shortfall honestly. Reference sample: £224.91 essentials against a £200 budget means £24.91 over.
  • Stock: Do not edit stock live unless you have rehearsed a safe, reversible change and restoration.
Do not promise a party-time schedule. Only demonstrate it if you have confirmed that the deployed agent actually offers and generates one.

If something goes wrong

No themes or a flow error

Do not change data live or claim success. Use your prepared screenshot/recording, identify it as a backup, and continue with the catalog and architecture explanation.

The amount is different

Pause before saving. Check theme, guests, budget, stock, and live data. Use the actual result only when you understand it; otherwise move to the backup.

The agent goes off script

Say: “Let me reset to the prepared scenario.” Start a fresh conversation and re-enter the scripted answers.

You cannot find the saved record

Search Event Plans by the plan number returned in chat. Do not repeat the save blindly; first check whether a record was created.

Keep the story truthful. If the live integration fails, say so plainly, show the prepared backup, and explain what would need investigation.

Audience Q&A prompts

  • Why use curated Theme Product mappings rather than ask a generative model to select products?
  • Which calculations belong in a flow instead of the conversation?
  • How would you add payment or inventory reservation safely?
  • What production controls would be needed for authentication, privacy, permissions, connection ownership, monitoring, and failure handling?

If asked about Business Central, Finance & Operations, or CRM

Those systems are not shown as connected in this demo. They could be integrated through approved connectors or APIs, but doing so requires additional flow work and a decision about which system owns product, price, inventory, customer, and order data.

Closing words

Theme Studio combines a guided Copilot Studio experience with flow-based calculations and Dataverse business records. The shopper sees a transparent plan and approves before it is saved. Today's demo stops at the saved plan—it does not charge a payment method or submit a fulfilment order.

Remember The connected Power Platform environment is the source of truth. Repository sources do not include the live tenant configuration or importable flow definitions. Verify the deployed agent, flows, data, and exact figures before presenting.
